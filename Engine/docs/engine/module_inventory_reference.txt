Epoch active inventory
======================

Public headers
- `Engine/include/epoch.engine.hpp`
- `Engine/include/engine.config.hpp`
- `Engine/include/epoch.config.hpp`
- supporting API/common headers under `Engine/include/`

Primary module families
- `core.*`, `context.*`, `platform.*`, `render.*`, `perf.*`, `updater.*` spine/runtime ownership
- `visuals.engine` central visual profile for frame clears, scene clears,
  object/selection colors, look markers, and editor opacity parity
- `ai.*` OS-model selection, model-asset metadata, evidence packets, eval gates,
  and MCP/tool-harness planning surfaces
- `voxel.*` core multi-informational voxel field and trace/query contracts
- `forest.factory` deterministic built-in Forest Factory contracts; project assets
  remain opt-in through package activation
- `package.registry` source-owned package descriptors for runtime-minis,
  core opt-in packages, and research/downloadable package candidates
- `opengl.*`, `sdl.*`, `raylib.*`, `sfml.*`, `software.*`, `vulkan.*`, `noop.context` backend/context integrations
- `ecs.*` ECS surfaces; legacy names are historical, not current ownership
- `atlas.*`, sprite, image, texture, and GUI support
- `epoch.*` higher-level engine/runtime entry surfaces that still intentionally brand the top-level API

Ownership and implementation
- Module interfaces remain in Engine/modules; import identities do not change
  when implementation files move into subsystem folders.
- Engine/src/core holds primitive implementations; Engine/src/epoch holds
  composition, internal legacy runtime and entry implementation.
- Engine/src/render holds backend-neutral implementation; renderer adapters
  remain under Engine/src/renderers/<backend>.
- Engine/src/epochgui owns engine/font adapters; Engine/dep/EpochGui is the
  exact portable-library mirror, not another engine adapter copy.
- See source_naming_architecture.md and repository_layout_reference.txt for
  naming, internal/public headers, cache and source authority.
- Historical rename mappings belong in legacy_feature_map.md and Git history;
  they are not instructions to re-run a completed migration.

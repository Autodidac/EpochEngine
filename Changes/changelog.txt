# Epoch Changelog

## [v0.87.60] - Linux updater visibility and toolchain repair

- Promoted the Linux cancel/progress, managed registry, tool-cache diagnostics,
  and Clang 22 CI workaround into a replacement Windows/Linux runtime release.

## [v0.87.59] - Post-release source checkpoint

- Advanced `main` after the proven `v0.87.58` Windows/Linux runtime release so
  packaged installs can exercise the repaired Linux source-update lane.
- Linux in-process source rebuilds now expose active/cancel state during
  download, registry preparation, dependency restore, and compilation; the
  editor modal reads live evidence instead of presenting generic 94% staging.
- Reduced managed-vcpkg Git staging to registry-owned paths and added visible
  registry milestones and cancellation checkpoints.
- Added a source-local Clang 22 Release optimization workaround for the LLVM
  CGSCC crash observed in `core.commandline.ixx` on hosted Linux runners.

## [v0.87.58] - Linux managed-vcpkg updater completion

- Enabled updater subprocess-output capture on Linux so managed vcpkg archive
  snapshots can resolve the local Git revision required by manifest mode.
- Canonicalized and validated the managed registry `.git` path before accepting
  its revision, with explicit probe diagnostics retained in the update log.
- Kept the manifest-compatible managed vcpkg root pinned into `build.sh`, which
  prevents a stale user checkout from resolving newer ports against an older
  version database.
- Updater/bootstrap Linux builds now configure CMake fresh so a compiler or
  vcpkg-root change cannot reconfigure against stale system-package cache data.

## [v0.87.57] - Post-release source checkpoint

- Advanced `main` after v0.87.56 so packaged installs can exercise the repaired
  stale-vcpkg registry fallback through the normal source-update lane.

## [v0.87.56] - Linux updater registry repair

- Reject installed vcpkg checkouts whose working registry predates the source
  manifest baseline instead of treating a fetched but unselected commit as a
  usable version database.
- Updater-driven Linux builds now prepare an exact-baseline vcpkg checkout in
  the executable-local tool cache and regenerate CMake-policy overlays from
  that same registry. Existing packaged updaters can recover through the new
  source `build.sh`; newly compiled updaters reject stale roots before staging
  overlays.
- Moved `CommandQueue` construction into one module implementation unit so
  MSVC does not emit duplicates and Clang links mutex-bearing SDL/SFML state.

## [v0.87.55] - Post-release source checkpoint

- Advanced `main` after the corrected `v0.87.54` release so packaged installs
  can detect and exercise the repaired Linux source-update lane.

## [v0.87.54] - Replacement Linux startup and portable runtime repair

- Fixed the Linux OpenGL startup SIGSEGV caused by calling Raylib 6's embedded
  GLAD 2 `gladLoadGL` symbol through GLAD 1's incompatible zero-argument ABI.
- Linux binaries now use only `$ORIGIN/lib`, stage the Vulkan loader beside the
  existing SFML runtimes, and reject dependencies resolved from build caches.
- Linux release staging now launches an isolated, bounded OpenGL editor smoke
  after version and contract checks, so atlas/renderer startup must pass before
  an archive can be produced.

- Pinned and checksum-verified CMake 4.4.0, LLVM/Clang 22.1.8 with its matching
  module scanner, Ninja 1.13.2, and the vcpkg 2026.06.24 registry for Linux
  source updates.
- Restored the full Linux renderer build with OpenGL, Vulkan, SDL, SFML,
  Raylib, and Software enabled together under C++23 modules.
- Added the `x64-linux-epoch` vcpkg triplet: dependencies remain static except
  SFML, preventing its embedded STB implementation from colliding with
  Raylib's while retaining a compact package.
- Fixed strict Clang module ownership in Vulkan partitions and made the command
  queue own construction of its mutex-bearing state across module boundaries.
- Added verified third-party notices and tool-license provenance to release
  staging, plus real updater progress evidence from the Linux build script.

## [v0.87.52] - Linux updater repair

- Repaired Linux source updates so packaged installs resolve an installed vcpkg
  checkout first and otherwise bootstrap a validated executable-local managed
  vcpkg checkout before invoking the source build.
- The Linux source build now receives its selected vcpkg root and policy overlay
  explicitly, refreshes stale/partial managed tool caches, and stays on the
  supported Clang full-engine lane instead of falling back into experimental GCC
  module builds after a Clang failure.
- Repaired Engine CMake Tools metadata: tracked preset toolchain discovery,
  C++23 IntelliSense, no malformed kit path, and no stale script-debug launch
  target. Empty or missing `VCPKG_ROOT` values now produce a direct setup
  error instead of the misleading `/scripts/buildsystems/vcpkg.cmake` path.
- Replaced the local-only vcpkg merge baseline with a verified upstream registry
  commit shared by the Windows and Linux toolchains, and excludes the
  currently unsupported Linux Vulkan, SFML, and Raylib package lanes from
  Linux source-update installs while retaining the existing Linux SDL package
  policy and runtime context selection. The supported Linux release remains
  Clang, OpenGL, SDL, and software.
